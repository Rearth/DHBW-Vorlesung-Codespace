## Wie verwenden wir dieselbe Aufgabe an anderer Stelle?

```csharp
int firstWidth = 4;
int firstHeight = 3;
int firstArea = firstWidth * firstHeight;
Console.WriteLine(firstArea);

int secondWidth = 5;
int secondHeight = 2;
int secondArea = secondWidth * secondHeight;
Console.WriteLine(secondArea);
```


Note:
- Rechteckfläche: Breite mal Höhe; Ausgabe 12 und 10
- Maße jeweils in derselben Einheit; Ergebnis in Flächeneinheiten
- Auch einfache Berechnungen lassen sich als benannte Aufgabe bündeln
- Lösung mit Rückgabewert später gemeinsam entwickeln

## Eine Methode gibt einer Aufgabe einen Namen

Eine **Methode** fasst Anweisungen unter einem Namen zusammen.
Ein **Aufruf** führt diese Anweisungen aus.

```text
Hauptprogramm                  Baustein SayHello
„Begrüßung ausführen“   →       „Hallo!“ ausgeben
                       ←       Fertig: im Hauptprogramm weiter
```

**Definieren** heißt: Wir legen die Anweisungen fest.
**Aufrufen** heißt: Wir führen diese Anweisungen aus.

Note:
- Analogie: Arbeitsanleitung und Auftrag, sie jetzt auszuführen
- Eine geschriebene Anleitung arbeitet noch nicht von selbst
- Console.WriteLine ist bereits ein bekannter Methodenaufruf
- Unsere eigenen Bausteine im Top-Level-Code: technisch lokale Funktionen
- Hauptprogramm bezeichnet hier die direkt ausgeführten Anweisungen in Program.cs.
- Beispiele einzeln ausprobieren und dazu den bisherigen Inhalt von Program.cs ersetzen; die Folien sind kein fortlaufend zu ergänzendes Programm.


---

## Bisher: Anweisungen der Reihe nach ausführen

```csharp [1|2|3]
Console.WriteLine("Start");
Console.WriteLine("Hallo!");
Console.WriteLine("Ende");
```

```text
Start
Hallo!
Ende
```

Das Programm führt diese drei Anweisungen von oben nach unten aus.

Note:
- Bisheriges Denkmodell aktivieren: von oben nach unten
- Keine neue Berechnung; Aufmerksamkeit nur auf den Ablauf
- Gleich dieselbe Ausgabe mit einem eigenen Baustein erzeugen


---

## Jetzt: Hauptprogramm und Methodendefinition trennen

```csharp [1-3|5-8|2]
Console.WriteLine("Start");
SayHello();
Console.WriteLine("Ende");

void SayHello()
{
    Console.WriteLine("Hallo!");
}
```

**Zeilen 1 bis 3:** Der Ablauf im Hauptprogramm.
**Zeilen 5 bis 8:** Die Definition des Bausteins `SayHello`.

Unsere Bausteine direkt im Hauptprogramm heißen in C# **lokale Funktionen**. Aufruf, Parameter und Rückgabe lernen wir zunächst an dieser Form.

Note:
- Markierungen: zwei Bereiche zeigen; noch keine Ablaufspur
- Aufruf in Zeile 2 und Definition darunter gegenüberstellen
- void und () zunächst als Schreibweise übernehmen; Syntax später zerlegen
- Methodenkörper wird erst bei einem Aufruf ausgeführt


---

## Vor dem Start: Welche Bausteine gibt es?

Der **Compiler** prüft und übersetzt den Quelltext vor der Ausführung.
Dabei ordnet er die Aufrufe den passenden Definitionen zu.

Für unser Beispiel können wir uns diese Zuordnung merken:

| Name | Zugehörige Anleitung |
|---|---|
| `SayHello` | `Console.WriteLine("Hallo!");` |

Die Definition ist bekannt, obwohl sie **unter** dem Aufruf steht.
Ihr Inhalt wird dadurch noch nicht ausgeführt.

Note:
- „Bausteinverzeichnis“ als Denkmodell, keine echte Tabelle im Programm
- Nicht behaupten: laufendes Programm liest erst alle Zeilen und speichert Methoden
- Der Compiler kennt die Definitionen im jeweiligen Gültigkeitsbereich. Für Variablen gelten eigene Regeln.
- Start der Ausführung danach im Hauptprogramm, nicht in der ersten Definition
- Referenz: https://learn.microsoft.com/en-us/dotnet/csharp/fundamentals/building-software/local-functions


---

## Ablauf-Demo 1: im Hauptprogramm starten

```csharp [1]
Console.WriteLine("Start");
SayHello();
Console.WriteLine("Ende");

void SayHello()
{
    Console.WriteLine("Hallo!");
}
```

**Ausgabe bis hier:**

```text
Start
```

Note:
- Durchgehend dasselbe Programm; kein neuer Programmlauf auf der nächsten Folie
- Finger/Zeiger auf die aktuell ausgeführte Anweisung setzen
- Nächster Schritt ist der Aufruf, noch nicht die Ende-Ausgabe

```csharp [2|7]

Console.WriteLine("Ende");

}
```

**Ausgabe bis hier:**

```text

```

Note:
- Zeile 2: Hauptprogramm wartet; Fortsetzung bei Zeile 3 merken
- Dann Zeile 7: Anweisung im Methodenkörper ausführen
- Nicht alle Definitionen durchlaufen; gezielt den benannten Baustein aufrufen

## Ablauf-Demo 3: nach dem Aufruf weiterarbeiten

```csharp [3]
Console.WriteLine("Start");
SayHello();
Console.WriteLine("Ende");

{
    Console.WriteLine("Hallo!");
}
```

**Gesamtausgabe:**

```text
Start
Hallo!
Ende
```

Note:
- Am Ende der Methode geht es an der gemerkten Stelle weiter.
- Rückkehr passiert auch ohne ausgeschriebenes return
- Danach endet hier das Hauptprogramm; Definition nicht noch einmal ausführen

## Was bedeutet jetzt „von oben nach unten“?

```text
Hauptprogramm                    SayHello
1. „Start“ ausgeben
2. SayHello aufrufen      →       „Hallo!“ ausgeben
   Auf die Methode warten        Ende der Methode
3. „Ende“ ausgeben        ←       Zum Hauptprogramm zurückkehren
```

Das Hauptprogramm arbeitet seine Anweisungen der Reihe nach ab.
Bei einem Aufruf führt es zuerst die Methode aus.
Danach geht es im Hauptprogramm weiter.

Note:
- Kein beliebiger Sprung: Aufruf hat einen Namen und eine Rückkehrstelle
- Hauptprogramm nicht neu starten; Definition nicht „von dort bis Dateiende“ abarbeiten
- Kurze Tafelanimation: Pfeil hin, Fortsetzungsmarke setzen, Pfeil zurück
- Hier wartet das Hauptprogramm, bis der Methodenaufruf fertig ist.

## Eine Methode ohne Eingaben und ohne Ergebnis

```csharp [3|4-6|1]
SayHello();

void SayHello()
{
    Console.WriteLine("Hallo!");
}
```

| Bestandteil | Bedeutung |
|---|---|
| `void` | Die Methode gibt keinen Wert zurück |
| `SayHello` | Name des Bausteins |
| `()` | Die Methode braucht hier keine Eingabewerte |
| `{ ... }` | Anweisungen für jeden Aufruf |

Note:
- Erst jetzt die bereits erlebte Schreibweise zerlegen
- Aufruf mit ;, Methodenkopf ohne ;; Namen in PascalCase
- void verhindert keine Ausgabe und keine Rückkehr zum Aufrufer


---

## Eine Methode zweimal aufrufen

```csharp [1|6|2|3|6]
SayHello();
Console.WriteLine("Pause");
SayHello();
void SayHello()
{
    Console.WriteLine("Hallo!");
}
```

```text
Hallo!
Pause
Hallo!
```

Jeder Aufruf beginnt erneut am Anfang des Methodenkörpers.

Note:
- Rückkehr nach erstem Aufruf zur Pause-Ausgabe, nach zweitem zum Programmende
- Definition bleibt dieselbe; Aufrufe sind zwei getrennte Ausführungen
- Keine Schleife nötig; keine dauerhafte Verbindung zur Aufrufstelle


---

## Die Aufrufe legen die Reihenfolge fest

```csharp [1|10|2|6]
PrintFooter();
PrintHeader();

void PrintHeader()
{
    Console.WriteLine("Willkommen!");
}
void PrintFooter()
{
    Console.WriteLine("Bis bald!");
}
```

**Ausgabe:** zuerst `Bis bald!`, danach `Willkommen!`.

Note:
- Definition von PrintHeader steht zuerst, wird trotzdem später aufgerufen
- Hauptprogramm bestimmt Reihenfolge durch Aufrufe; Namen haben keine Sonderwirkung
- Nicht aufgerufene Methode erzeugt gar keine Ausgabe
- Live: einen Aufruf entfernen; Definition unverändert lassen

3. Rufen Sie die Methode im Hauptprogramm genau einmal auf.

**Kontrolle:** Der Name erscheint genau einmal.

- 3 bis 4 Min.; möglichst ohne Vorlage schreiben

## Aufgabe 2: Mehrere Bausteine aufrufen

**Ziel:** Mehrere Methoden in einer festen Reihenfolge aufrufen.

1. Schreiben Sie `PrintHeader` und `PrintFooter`, jeweils ohne Parameter mit Rückgabetyp `void`.
2. `PrintHeader` gibt `Willkommen!` aus, `PrintFooter` gibt `Bis bald!` aus.
3. Erzeugen Sie im Hauptprogramm: `Willkommen!`, `Programminhalt`, `Bis bald!`.

**Kontrolle:** Die Ausgabe folgt der Reihenfolge der Aufrufe.

Note:
- 4 bis 5 Min.; Programminhalt mit WriteLine im Hauptprogramm ausgeben
- Erst erwartete Ausgabe notieren, dann Programm ausführen

## Aufgabe 3: Eine Anleitung mehrfach verwenden

**Ziel:** Wiederholte Anweisungen einmal definieren.

2. Die Methode gibt zwei Zeilen aus: `Informationstechnologie I` und `Eigene Methoden`.
3. Rufen Sie sie auf, geben Sie im Hauptprogramm `Pause` aus und rufen Sie sie erneut auf.

**Kontrolle:** Die beiden Aufrufe geben jeweils dieselben zwei Zeilen aus. Dazwischen steht `Pause`. Insgesamt erscheinen fünf Zeilen.

- 4 bis 5 Min.; beide WriteLine-Anweisungen gehören in denselben Körper
- Kein Kopieren der Ausgaben ins Hauptprogramm; zwei Aufrufe genügen
- Rückkehr jeweils an andere Stelle zeigen lassen
- Eine Definition führt noch nichts aus. Die Aufrufe bestimmen die Reihenfolge.

## Eingaben und Ergebnisse einer Methode

Wir rufen die Methode auf. Sie führt ihre Anweisungen aus. Dann kehrt sie zurück.
Methoden können Eingabewerte erhalten und Ergebniswerte zurückgeben:

```text
Eingabewert       Methode                   Rückgabewert
5 und 3    →      Add: Zahlen addieren  →    8
```

Zuerst betrachten wir Eingabewerte, danach Ergebniswerte.

Note:
- Erst nach Aufgaben 1 bis 3; Ablaufprinzip muss verstanden sein
- Ein Aufruf braucht nicht zwingend Eingabewerte oder ein Ergebnis
- Rückkehr zum Aufrufer bleibt; ob ein Ergebniswert mitkommt, bestimmt der Rückgabetyp
- Vorschau auf Add; zuerst mit Greet nur die Eingabeseite betrachten
- Analogie: Anleitung bleibt gleich, eingesetzte Werte können wechseln


---

## Texte mit `+` zusammensetzen

Bei Zahlen addiert `+` die Werte. Bei Strings verbindet `+` die Texte.
Das heißt **String-Verkettung**.

```csharp
Console.WriteLine(3 + 4);             // 7
Console.WriteLine("3" + "4");         // 34

string name = "Mia";
string begruessung = "Hallo, " + name + "!";
Console.WriteLine(begruessung);       // Hallo, Mia!
```

Leerzeichen müssen im Text stehen: `"Hallo, "` enthält das Leerzeichen nach dem Komma.

Note:
- Kurz vor dem ersten Greet-Beispiel einführen
- Anführungszeichen unterscheiden Zahl und Text: 3 gegenüber "3"
- Die Verkettung ergibt einen neuen String, der gespeichert oder ausgegeben werden kann
- name auf "Noah" ändern und die neue Begrüßung vorhersagen lassen


---

## Parameter geben der Methode Werte mit

```csharp [1-2|4|6]
Greet("Mia");
Greet("Noah");

void Greet(string name)
{
    Console.WriteLine("Hallo, " + name + "!");
}
```

**Ausgabe:**

```text
Hallo, Mia!
Hallo, Noah!
```

`name` erhält bei jedem Aufruf den übergebenen Text. `+` setzt hier Texte zusammen.

Note:
- Eingabe ist hier ein übergebener Wert, keine Tastatureingabe
- Wert wie beschrifteten Zettel in den Baustein geben: name = "Mia", dann "Noah"
- Textverkettung kurz zeigen: "Hallo, " + "Mia" + "!" ergibt "Hallo, Mia!"; keine Interpolation voraussetzen
- Erst Vorhersage; dann Eingabewert ändern


---

## Parameter und Argument unterscheiden

```csharp [1-2|4]
string student = "Mia";
Greet(student);

void Greet(string name)
{
    Console.WriteLine("Hallo, " + name + "!");
}
```

- In der Definition steht der **Parameter** `string name`.
- Beim Aufruf steht das **Argument** `student`. Sein Wert ist `"Mia"`.
- Die Variable außen und der Parameter dürfen verschiedene Namen haben.

Note:
- Wert übergeben, keine Verbindung über gleiche Namen
- Argument kann Literal, Variable oder Ausdruck sein
- Greet("Mia"); und Greet(student); hier gleiche Ausgabe
- Parameter ist eine lokale Variable des jeweiligen Aufrufs


---

## Mehrere Parameter: Typ und Reihenfolge beachten

```csharp [1|3|5-8]
PrintDifference(10, 3);

PrintDifference(3, 10);

void PrintDifference(int left, int right)
{
    Console.WriteLine(left - right);
}
```

**Ausgabe:** zuerst `7`, dann `-7`.

Das erste Argument wird an `left` übergeben. Das zweite wird an `right` übergeben.

Note:
- Gemeinsam zuordnen: left erhält 10. right erhält 3.
- Beim Aufruf keine Parametertypen hinschreiben
- Anzahl und Typen müssen passen; PrintDifference("10", 3) ungültig
- Benannte/optionale Argumente heute auslassen

## Rückgabewert: ein Ergebnis weiterverwenden

```csharp [4|6|1|2]
int result = Add(5, 3);
Console.WriteLine(result);

int Add(int left, int right)
{
    return left + right;
}
```

- `int` vor dem Namen bedeutet: Die Methode liefert eine ganze Zahl.
- `return` liefert das Ergebnis an die Aufrufstelle zurück.
- Die Variable `result` speichert hier den Wert `8`.

Note:
- Highlights erklären Bestandteile; Ablauf nächste Folien
- Definition „verspricht“ int; Rückgabe muss zu int passen
- Add selbst schreibt nichts auf die Konsole
- Bekanntes Zurückkehren bleibt; neu ist der dabei gelieferte Wert
- An der Tafel zeigen: Add erhält 5 und 3. Die Methode liefert 8. result speichert 8.


---

## Rückgabe-Demo: zuerst die Methode ausführen

```csharp [1|4|6]
int result = Add(5, 3);
Console.WriteLine(result);

int Add(int left, int right)
{
    return left + right;
}
```

`left` enthält `5`. `right` enthält `3`. Mit `return` gibt die Methode `8` zurück.

**Bisher wurde nichts ausgegeben.** Die Variable `result` erhält ihren Wert erst nach der Rückgabe.

Note:
- Stand unmittelbar vor Abschluss der Zuweisung
- Erst rechte Seite berechnen; dann links speichern
- Ausdruck gedanklich ersetzen: int result = 8;
- Parameter gehören zu diesem Aufruf


---

## Rückgabe-Demo: Ergebnis speichern und ausgeben

```csharp [1|2]
int result = Add(5, 3);
Console.WriteLine(result);

int Add(int left, int right)
{
    return left + right;
}
```

Nach dem Aufruf enthält `result` den Wert `8`.

**Ausgabe nach Zeile 2:** `8`

Note:
- Rückkehr zur Aufrufstelle, nicht Neustart des Hauptprogramms
- result wird erst nach Rückgabe zugewiesen
- Add(10, 20) ergibt unabhängig davon 30

## Ausgeben und zurückgeben sind verschiedene Aufgaben

```csharp
void PrintSum(int left, int right)
{
    Console.WriteLine(left + right);
}

int Add(int left, int right)
{
    return left + right;
}
```

| Aufruf | Wirkung |
|---|---|
| `PrintSum(5, 3);` | Schreibt `8` auf die Konsole |
| `int total = Add(5, 3);` | Speichert `8`; keine Ausgabe |

Note:
- int total = PrintSum(5, 3); ungültig: void ist kein Wert
- Add(5, 3); allein erlaubt, Ergebnis bleibt ungenutzt
- Reine Berechnung kann später in Konsole/Web/App verwendet werden
- Ausgabe ist keine Rückgabe an eine Variable

## Einen Rückgabewert weiterverwenden

```csharp
int result = Add(5, 3);
int doubled = result * 2;
Console.WriteLine(doubled);

Console.WriteLine(Add(10, 20));

int Add(int left, int right)
{
    return left + right;
}
```

**Ausgabe:** `16`, danach `30`.

Wir können den Rückgabewert speichern, damit weiterrechnen oder ihn direkt ausgeben. Bei `Console.WriteLine(Add(10, 20))` wird zuerst `Add` ausgeführt, dann `30` ausgegeben.

Note:
- Verschachtelter Aufruf: erst Add, dann WriteLine
- Add(5, 3) * 2 als mögliche Kurzform ergänzen
- Zum Debuggen Zwischenergebnisse separat speichern

## `return` beendet den aktuellen Aufruf

```csharp [1|3|5-8|9]
Console.WriteLine(IsAdult(20));

bool IsAdult(int age)
{
    if (age >= 18)
    {
        return true;
    }
    return false;
}
```

Bei `20` gibt die Methode `true` zurück. Das Programm gibt `True` aus.
Bei `17` gibt die Methode `false` zurück. Das Programm gibt `False` aus.

Note:
- Markierungen: Syntaxteile; Zeile 9 läuft bei 20 nicht
- Kein else nötig, weil erster Fall die Methode verlässt
- Die Methode muss in jedem Fall einen bool zurückgeben, wenn sie normal endet.
- Ohne das zweite return fehlt die Rückgabe für age < 18. Der Compiler meldet einen Fehler.


---

## Eine Bedingung ist bereits ein `bool`-Wert

```csharp
bool IsAdult(int age)
{
    return age >= 18;
}
```

```csharp
int age = 20;
if (IsAdult(age))
{
    Console.WriteLine("Zutritt ab 18 erlaubt.");
}
```

`IsAdult(age)` kann überall stehen, wo ein `bool` benötigt wird.

Note:
- Zwei Ausschnitte gehören zusammen; Definition allein erzeugt keine Ausgabe
- Erst ausgeschriebene if/return-Version verstehen; dann kürzen
- Kein == true nötig
- Ausgabe fachlich nur Altersprüfung, keine Ticketprüfung

## Dieselbe Methode mit unterschiedlichen Werten verwenden

```csharp [6-9|1-2|3-4]
int firstArea = CalculateRectangleArea(4, 3);
Console.WriteLine(firstArea);
int secondArea = CalculateRectangleArea(5, 2);
Console.WriteLine(secondArea);

int CalculateRectangleArea(int width, int height)
{
    return width * height;
}
```

**Ausgabe:** `12`, danach `10`.

Die Formel steht nur einmal in der Methode. Jeder Aufruf berechnet ein neues Ergebnis.

Note:
- Einstiegsbeispiel wieder aufgreifen: kopierte Formel durch Aufrufe ersetzen
- Markierungen: Definition, dann beide Aufrufe; keine Ablaufspur
- Beim ersten Aufruf: width ist 4, height ist 3. Beim zweiten Aufruf: width ist 5, height ist 2.
- Die Maße sind ganze Zahlen ab 0. Für Dezimalzahlen können wir später double verwenden.

## Gültigkeitsbereich: Wo ist eine Variable sichtbar?

```csharp [1-3|5-9]
int firstNumber = 5;
int result = DoubleValue(firstNumber);
Console.WriteLine(result);

int DoubleValue(int value)
{
    int doubled = value * 2;
    return doubled;
}
```

`value` und `doubled` können nur innerhalb von `DoubleValue` verwendet werden.
Mit dem Rückgabewert können wir das Ergebnis im Hauptprogramm verwenden.

Note:
- Console.WriteLine(doubled); ist im Hauptprogramm nicht erlaubt. Der Compiler meldet einen Fehler.
- Gültigkeitsbereich heißt auch Scope. Er beschreibt, wo ein Name im Code sichtbar ist.
- Jeder Aufruf hat eigene Parameter/lokale Variablen
- Lokale Funktionen können äußere Variablen erfassen; hier bewusst Parameter nutzen
- Referenz: https://learn.microsoft.com/en-us/dotnet/csharp/programming-guide/classes-and-structs/local-functions

## Wertübergabe: Der Parameter erhält eine Kopie

```csharp [1|2|7|8|3]
int number = 5;
PrintIncreased(number);
Console.WriteLine(number);

void PrintIncreased(int value)
{
    value = value + 1;
    Console.WriteLine(value);
}
```

## Wertübergabe, `ref` und `out` vergleichen

| Übergabe | Wert vorher nötig? | Zuweisung an Parameter |
|---|---|---|
| `int value` | Ja | Ändert die lokale Kopie |
| `ref int value` | Ja | Ändert die Variable des Aufrufers |
| `out int value` | Nein | Muss vor der Rückkehr einen Wert in die Variable des Aufrufers schreiben |

Für ein Ergebnis verwenden wir meist `return`.
Mit `ref` können wir eine vorhandene Variable ändern.
Mit `out` können wir weitere Ergebnisse liefern.

Note:
- Tabelle bezieht sich auf int und Parameterzuweisungen
- out darf vorher schon initialisiert sein; alter Wert ist nicht die Eingabe
- ref muss den Wert nicht ändern; out muss einen zuweisen
- Nicht mit Referenztypen verwechseln

## `in`: eine Variable schreibgeschützt übergeben


## Rekursion: eine Methode ruft sich selbst auf

Eine Methode kann sich selbst aufrufen. Das nennen wir **Rekursion**.

Wir wollen die Summe aller ganzen Zahlen von `1` bis `n` berechnen.

```text
SumUpTo(4) = 4 + SumUpTo(3)
SumUpTo(3) = 3 + SumUpTo(2)
SumUpTo(2) = 2 + SumUpTo(1)
SumUpTo(1) = 1
```

Jeder Aufruf berechnet eine kleinere Summe.
Bei `n = 1` kennen wir das Ergebnis bereits.

Note:
- Summe zuerst an 1 + 2 + 3 + 4 erklären; keine Fakultätsnotation nötig
- Eingaben sind positive ganze Zahlen. Der Basisfall ist n == 1.
- Resultat 10 vorab gemeinsam berechnen
- Aufrufe müssen später mit ihren Ergebnissen zurückkehren


---

## Rekursion braucht einen erreichbaren Basisfall

```csharp [1|3|5-8|9]
Console.WriteLine(SumUpTo(4));

int SumUpTo(int n)
{
    if (n == 1)
    {
        return 1;
    }
    return n + SumUpTo(n - 1);
}
```

**Voraussetzung:** `n >= 1`.

Bei `n == 1` endet die Rekursion. Das ist der **Basisfall**.
Sonst ruft sich die Methode mit `n - 1` auf.

Note:
- Markierungen: Bestandteile, keine vollständige Ablaufspur
- Weniger Arbeit pro Teilproblem; n nähert sich 1
- n = 0/negative Werte erfüllen Voraussetzung nicht; hier nicht ausführen


---

## Rekursions-Demo: Aufrufe bauen sich auf

```text
SumUpTo(4) wartet auf 4 + SumUpTo(3)
  SumUpTo(3) wartet auf 3 + SumUpTo(2)
    SumUpTo(2) wartet auf 2 + SumUpTo(1)
      SumUpTo(1) liefert 1
```

Jeder Aufruf besitzt seinen eigenen Parameter `n`.

Die äußeren Additionen warten auf das Ergebnis des nächsten Aufrufs.

Note:
- Tafel: vier Aufrufkarten mit n = 4, 3, 2, 1
- Der Aufrufstapel heißt auch Call Stack. Er enthält die laufenden Aufrufe und ihre Rückkehrstellen.
- n der wartenden Aufrufe wird nicht durch n - 1 überschrieben
- Noch kein WriteLine: zuerst SumUpTo vollständig auswerten


---

## Rekursions-Demo: Ergebnisse kehren zurück

```text
      SumUpTo(1) liefert 1
    SumUpTo(2) berechnet 2 + 1 = 3
  SumUpTo(3) berechnet 3 + 3 = 6
SumUpTo(4) berechnet 4 + 6 = 10
```

```csharp
Console.WriteLine(SumUpTo(4));
```

Erst nach allen Rückgaben wird **`10`** ausgegeben.

Note:
- Gleiche Einrückung wie beim Aufbau: Rückgaben führen wieder nach außen.
- Die Karten rückwärts abbauen. Der letzte Aufruf wird zuerst fertig.
- Pro Rückkehr genau eine wartende Addition abschließen
- Vorwärts kleinere Probleme; rückwärts fertige Ergebnisse

## Schleife und Rekursion im Vergleich

| Frage | Schleife für die Summe | Rekursive Summe |
|---|---|---|
| Wie wiederholen? | Nächster Schleifendurchlauf | Neuer Methodenaufruf |
| Wo steckt der Zustand? | Zähler und laufende Summe | Eigene Werte je Aufruf |
| Wann endet es? | Bedingung wird `false` | Basisfall wird erreicht |
| Zusätzlicher Speicher | Feste Anzahl Variablen | Wächst hier mit der Aufruftiefe |

Für eine einfache laufende Summe ist eine Schleife meist naheliegend.
Rekursion hilft etwa bei verschachtelten Strukturen.

Note:
- Die Summe mit einer Schleife und die gezeigte rekursive Summe vergleichen.
- Ohne erreichbaren Basisfall oder bei zu großer Tiefe: Stacküberlauf
- StackOverflowException nicht live provozieren
- Große Summen können zusätzlich den int-Wertebereich überschreiten
- Beispiel verschachtelte Struktur: Ordner mit Unterordnern; keine Implementierung
